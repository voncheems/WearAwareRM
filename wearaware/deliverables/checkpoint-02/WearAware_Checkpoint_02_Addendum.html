Deployed demo

Frontendhttps://wearaware-demo.vercel.app — React/Vite frontend deployed on Vercel over HTTPS.
Backend and databaseThe Express API and MongoDB remain on the demonstration laptop. A Cloudflare Quick Tunnel provides the temporary HTTPS connection used by the Vercel frontend.
AI inferenceThe protected FastAPI/YOLO service runs locally beside the backend. The browser never receives the model’s shared API key; Express authenticates the inspector upload before forwarding it to the local service.

Demo limitation: this is a presentation deployment, not a permanent production backend. The laptop, MongoDB, backend, Python model process, and Cloudflare tunnel must remain running. A Quick Tunnel URL can change when restarted, requiring a frontend redeploy with the new API origin.

Recent functionality

  • Added the User role, linked to a worker account. Users can view their own QR code, inspection history, and personal compliance rate. Server-side ownership checks prevent a user from accessing another worker’s records.
  • Completed the admin user-management workflow, including role selection, worker linking, active-status management, and the User role’s required unique worker association.
  • Updated the admin and inspector dashboards with the same responsive visual system and logout controls.
  • Improved QR scanning resilience with a retry for transient lookup failures and timeouts appropriate for the tunnel-backed demo.
  • Improved scanner continuity: after a completed scan, the scanner returns to QR mode for the next worker.
  • Changed detection lists so they return only a has_photo flag. Full camera photos load only after an administrator or inspector selects the record, reducing dashboard payload and initial loading time.
  • Adjusted PPE inference so a detected person with neither recognised helmet nor vest is recorded as an inferred no-helmet and no-vest violation. The camera confidence input was lowered from 0.35 to 0.25 while class-specific PPE filtering remains in place.

Security controls implemented

  • JWT authentication with active-account and current-database role checks for Administrator, Inspector, and User roles.
  • Role-based route authorization and inspector station/worker scope enforcement.
  • Typed request validation, strict MongoDB collection validators, unique indexes, safe error responses, and constrained photo/image validation.
  • Helmet security headers, explicit CORS origins, request-size limits, authentication rate limits, password-strength validation, and production configuration checks.
  • Single-use, expiring password recovery links; reset requests store a hash rather than a reusable plaintext password.
  • Authenticated WebSocket alerts scoped to the assigned inspector. Tokens are not placed in WebSocket URLs.
  • Protected AI uploads: inspector authorization, JPEG/PNG and size limits, backend-held service key, one-at-a-time inference, and safe failure responses.

Known limitation: browser bearer tokens are currently stored in localStorage. A future improvement is an HttpOnly-cookie session design with CSRF protection. The Quick Tunnel is suitable for a controlled demo, not a permanent production exposure.

Updated request flow

Vercel React frontend → Cloudflare Quick Tunnel (HTTPS) → Express API on the demo laptop → local MongoDB for application records. For PPE scans, Express additionally forwards the authenticated image to the localhost FastAPI/YOLO service using a private service key. The result returns through Express to the browser. This design keeps database credentials, JWT secrets, and the AI key out of the frontend build.

Run requirements for the demo

Before presenting, keep the following processes running on the same laptop: local MongoDB, npm --prefix src/wearawarebackend start, the FastAPI/YOLO service on port 8000, and cloudflared tunnel --url http://127.0.0.1:5000. The frontend does not require npm run dev while using the Vercel URL. See docs/FREE-DEMO.md for the current setup steps.
